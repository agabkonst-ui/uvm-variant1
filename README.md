# Ассемблер УВМ — вариант 1, этап 1

Ассемблер читает программу на JSON и переводит её в список словарей с полями
`A`–`E`. Порядок команд сохраняется. В тестовом режиме поля каждой команды
выводятся отдельной строкой в порядке, заданном спецификацией УВМ.

## Запуск

Требуется Python 3.10 или новее. Все команды ниже выполняются из корня проекта.
Сборка и установка сторонних зависимостей не требуются.

```powershell
.\run.bat tests\spec_program.json build\program.bin --test
```

В Windows скрипт пробует `py -3`, затем ищет `python.exe` в `PATH`.
При необходимости полный путь можно задать в переменной `UVM_PYTHON`.
Прямой запуск на любой платформе выглядит так.

```sh
python -B src/assembler.py tests/spec_program.json build/program.bin --test
```

| Аргумент | Назначение |
| --- | --- |
| `source` | Путь к исходной JSON-программе в UTF-8. |
| `output` | Обязательный путь для будущего двоичного файла. Запись файла предусмотрена на этапе 2. |
| `--test` | Печать промежуточного представления. Без флага успешная трансляция проходит без вывода. |
| `--help` | Справка по аргументам. |

При успехе код завершения равен `0`. При ошибке чтения или разбора выводится
сообщение в поток ошибок и возвращается `1`. Ошибки аргументов дают код `2`.
Ошибки в командах сопровождаются номером команды, начиная с единицы.

## Язык ассемблера

Программа представляет собой JSON-массив. Каждый элемент — объект с именем
операции `op` и её операндами. Все указанные для операции ключи обязательны.
Имена операций и ключей чувствительны к регистру. Лишние и повторяющиеся ключи
отклоняются. Операнды задаются целыми неотрицательными числами JSON. Верхняя
граница определяется шириной поля.

| Операция | Назначение | Поля промежуточного представления |
| --- | --- | --- |
| `load_const` | Загрузить константу `value` в регистр `dst`. | `A=0`, `B=dst`, `C=value` |
| `read_mem` | Прочитать память по адресу `address` в регистр `dst`. | `A=25`, `B=dst`, `C=address` |
| `write_mem` | Записать значение регистра `src` в память по адресу из `addr_reg`. | `A=32`, `B=src`, `C=addr_reg` |
| `mul` | Умножение с чтением операнда из памяти. | `A=23`, `B=offset`, `C=lhs`, `D=base`, `E=dst` |

Команда `mul` умножает содержимое регистра `lhs` на значение по адресу
`base + offset` и пишет результат в `dst`. Для вычисления адреса берётся
содержимое регистра `base`.

| Операнд | Диапазон включительно |
| --- | --- |
| Индекс регистра `dst`, `src`, `addr_reg`, `lhs` или `base` | `0`–`15` (4 бита) |
| Константа `value` | `0`–`16777215` (24 бита) |
| Адрес памяти `address` | `0`–`524287` (19 бит) |
| Смещение `offset` | `0`–`8191` (13 бит) |

В [тестовой программе](tests/spec_program.json) собраны четыре примера
из спецификации варианта 1.

```json
[
  {"op": "load_const", "dst": 12, "value": 851},
  {"op": "read_mem", "dst": 9, "address": 937},
  {"op": "write_mem", "src": 8, "addr_reg": 0},
  {"op": "mul", "offset": 251, "lhs": 3, "base": 15, "dst": 15}
]
```

Ожидаемый вывод с `--test`.

```text
(A=0, B=12, C=851)
(A=25, B=9, C=937)
(A=32, B=8, C=0)
(A=23, B=251, C=3, D=15, E=15)
```

## Автоматические тесты

```sh
python -B -m unittest discover -s tests -v
```

При использовании Windows Python Launcher введите `py -3` вместо `python`.
Если PowerShell выбирает псевдоним Microsoft Store, укажите полный путь к
установленному `python.exe` с оператором `&` вместо `python`.
Тесты сравнивают внутреннее представление и вывод CLI с четырьмя эталонами,
проверяют допустимые границы операндов, ошибки ввода и оба режима запуска.
